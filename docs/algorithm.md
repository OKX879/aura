# 算法说明

这一篇只讲"为什么这么写"。参数表和踩坑记录都在这里，代码里的常量与本文一一对应。

## 1. 从 cube 到位移

雷达每个采样点给出一个 8 通道 × 30 距离门的复数 cube。板端按 90 Hz 连续采帧，维护一个 10.24 秒（922 点）的滑窗，每 90 点（1 秒）推进一步。

处理顺序：

1. **距离维 FFT + 杂波抑制**：去掉静止背景，保留与人体相关的复数值。
2. **距离门打分**：`aura_score_bin()` 综合能量、相位稳定性、跨通道一致性给每个距离门打分，`aura_score_window()` 汇总成一个窗口分数。
3. **距离锁定**：`aura_distance_lock_update()` 带滞后和跳门惩罚。人呼吸时胸廓位移会让主能量门在相邻门之间移动，如果每帧都取最大能量门，相位会出现阶跃。锁定后只在候选门连续胜出时才切换。
4. **复数融合**：`aura_fuse_trajectory()` 在多通道之间做相位对齐和加权融合，输出相位 `ph` 与幅度 `am`。
5. **相位转位移**：`mm = phase × 5 / (4π)`，波长按 5 mm 计。

`mm` 是后续所有体征估计的唯一输入。它的质量决定了上限。

## 2. 呼吸率

### 为什么是 30 秒窗

呼吸周期 3–5 秒。8 秒窗只能装下 2 个周期，FFT 分辨率约 7.5 次/分，相邻的 16 和 18 次/分根本分不开。

板端维护一个 50 秒的宽带位移历史 `wide`，呼吸估计取最近 30 秒：

```
nperseg = min(n, 2048)      // 30 s × 90 Hz = 2700，实际用 2048
window  = Hann
overlap = 50%
```

频率分辨率 90 / 2048 ≈ 0.044 Hz ≈ 2.6 次/分，再做抛物线插值细化。

### 频带为什么是 0.18–0.50 Hz

下边界最初是 0.14 Hz（8.4 次/分）。实测发现 30 秒窗里会同时出现两个能量相当的峰：10.5 次/分的基线漂移和 18.5 次/分的真实呼吸。输出因此在两者之间反复跳变。

把搜索下边界抬到 0.18 Hz（约 11 次/分）后，漂移被排除，输出稳定在 18.5。代价是测不到 10 次/分以下的极慢呼吸，这在静息成人场景下可以接受。

> 注意：这里改的是**峰值搜索区间**，滤波器本身没有换。0.18 Hz 以上的呼吸成分不受影响。

### 输出门限

- 峰值必须在 7–28 次/分之间
- 峰值 / 带内中位数 ≥ 1.8，否则视为不可信
- 不可信时最多沿用上一帧结果 8 帧，避免曲线抖动

## 3. 心率

心率比呼吸难一个数量级：心搏引起的胸壁位移只有 0.05–0.2 mm，而呼吸谐波可以到毫米级。

### 3.1 因果带通

先用 4 级二阶节把位移滤到 1.0–2.5 Hz（60–150 BPM），滤波器状态跨窗保留（`zi`），等价于一条连续的因果带通。

因果滤波会带来相位延迟，但对频率估计没有影响，而且比零相位滤波更适合流式输出。

### 3.2 呼吸谐波陷波

这是最容易翻车的一步。

设呼吸频率 `f_resp`，它的各阶谐波 `k·f_resp` 会落进心率带。呼吸 18.5 次/分时，4 次谐波正好是 74 次/分，而 74 在心率搜索带正中间，能量往往比真实心搏还大。如果直接取心率带的谱峰，会稳定地得到呼吸谐波。

`aura_rhc_notch()` 的做法：

- 对 `k·f_resp` 落在 40–180 BPM 的谐波，在频域挖掉 ±0.06 Hz
- 40–60 BPM 的谐波不挖：这一段本身就是低心率区，挖掉风险大于收益
- 挖之前先找 3 个最强谱峰和 1 个自相关主峰作为"候选"，如果某个谐波在候选 6 BPM 以内，跳过不挖——避免把真实心搏当成谐波削掉

所以**陷波是否有效，完全取决于 `f_resp` 准不准**。呼吸估偏 10%，陷波就会落在错误的位置，心率随之被带偏。这也是为什么第 2 节要先把呼吸做稳。

### 3.3 三路估计

| 路径 | 方法 | 强项 | 弱项 |
|---|---|---|---|
| FFT | Welch + 谐波积谱（HPS） | 抗噪声，分辨率高 | 容易被谐波带偏 |
| ACF | 自相关主峰，带边缘惩罚 | 对周期性信号稳 | 分辨率受采样限制 |
| PPI | 峰值间期（事件/模板/寻峰三种策略） | 直接对应生理间期 | 搏动少时漏拍 |

三路互补，但权重不能平均。

### 3.4 融合

```
w_fft = clip(snr / 5, 0.1, 1.0)
w_acf = clip(acf_height, 0.1, 1.0)
w_ppi = clip((n_peaks - 4) / 12, 0.05, 1.0)
```

PPI 的权重直接跟搏动数挂钩：10 秒窗里只有 8–10 个搏动，漏一拍间期就翻倍，所以搏动少时把 PPI 压到 0.05–0.5。

融合规则：

- 三路最大差 < 8 BPM → 认为一致，按权重加权平均
- 不一致，但 FFT 与 ACF 相差 ≤ 10 BPM，而 PPI 明显离群 → 取 FFT 与 ACF 的均值，丢弃 PPI
- 其他情况 → 取三路中位数，抗单路偏移

### 3.5 分析窗与预热

心率分析窗用 `hrhist` 里最近 30 秒的连续带通信号，而不是当前 10 秒窗：

- 10 秒窗只有 8–10 个搏动，一次台阶伪迹就能把谱峰拉到 60 BPM
- 30 秒窗分辨率从 5.9 BPM 提到 2.6 BPM，瞬时伪迹被摊薄

**预热闸门**：分析窗不足 20 秒时，不把结果喂给速率平滑器。平滑器每秒最多变化 1.5 BPM，如果用它前几秒的坏值播种，要一分多钟才能爬回真值。实测启动 60 秒后输出仍停在 68.7，而真值是 70。

### 3.6 速率平滑器

`aura_rate_tracker_update()` 负责把逐帧估计变成可读数值：

| 参数 | 值 | 含义 |
|---|---|---|
| `max_delta` | 1.5 | 每次更新最多变化 1.5 BPM |
| `min_confidence` | 0.30 | 低于此置信度不接受更新 |
| `history_size` | 5 | 滑动中位数窗口 |
| `seed_streak` | 3 | 连续 3 次一致才锁定初值 |
| `seed_range` | 8.0 | 初值一致性容忍 8 BPM |
| `relock_gap` | 15.0 | 与当前值差距超过 15 BPM 才考虑重锁 |
| `relock_streak` | 3 | 连续 3 次才重锁 |

## 5. 失效模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 呼吸在 10 / 18 次分之间跳 | 频带下边界包含基线漂移 | 下边界抬到 0.18 Hz |
| 心率稳定偏低约 8–15 BPM | 心率谱峰是呼吸谐波 | 先修呼吸，再检查陷波 |
| 心率稳定偏高约一倍 | 倍频（取到二次谐波）或漏拍 | 检查 PPI 搏动数与 FFT/ACF 一致性 |
| 启动后读数缓慢爬升 | 平滑器用坏初值播种 | 预热 20 秒后再喂平滑器 |
| 心率偶发 130+ 尖峰 | 体动导致三路同时倍频，触发重锁 | 目前只靠 `motion` 标记提示，待改进 |
