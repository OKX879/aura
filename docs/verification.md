# 验证方法与结果

## 为什么不能只看板端数字

体征算法最容易犯的错误是"自洽但不正确"：板端输出很平滑，看起来像那么回事，实际测的是呼吸谐波或者基线漂移。要判断准不准，必须把原始信号拿出来，用一套独立实现重算，再和板端输出对比。

## 数据采集

板端内置两个诊断导出开关，只在设置环境变量时生效，正常运行时零开销：

| 环境变量 | 内容 | 上限 |
|---|---|---|
| `AURA_PHASE_DUMP` | 逐样本毫米位移 `n,mm` | 5400 行（60 秒 @ 90 Hz） |
| `AURA_SNAP_DUMP` | 逐帧输出 `frame,hr,resp_hz,conf,motion` | 5400 行 |

临时用 systemd drop-in 注入，采完即删：

```bash
mkdir -p /etc/systemd/system/aura.service.d
printf '[Service]\nEnvironment=AURA_PHASE_DUMP=/tmp/phase.csv\nEnvironment=AURA_SNAP_DUMP=/tmp/snap.csv\n' \
  > /etc/systemd/system/aura.service.d/zz-dump.conf
systemctl daemon-reload && systemctl restart aura.service
# 采 90 秒后取回
scp root@<board>:/tmp/phase.csv root@<board>:/tmp/snap.csv .
rm -rf /etc/systemd/system/aura.service.d && systemctl daemon-reload && systemctl restart aura.service
```

> 导出的 `mm` 已经过每窗去均值，和板端 `wide` 缓冲区里的样本一致，可以直接复算。原始数据涉及个人体征，不随仓库发布。

## 离线复算

`tools/verify/` 下的脚本用 scipy 复现板端的每一级处理，参数与 C 代码一一对应：

- 呼吸：4 阶 Butterworth 0.18–0.50 Hz 零相位滤波 → Welch（nperseg = min(n, 2048)，Hann，50% 重叠）→ 带内峰值 + 抛物线插值
- 心率：因果 1.0–2.5 Hz 滤波 → 谐波陷波 → Welch + 谐波积谱 → 自相关 → 峰值间期 → 三路融合

`replay_board_hr.py` 复现的是板端的 **FFT 单路**，用来判断"FFT 是否被呼吸谐波带偏"。板端最终输出还叠加了自相关、峰值间期和 1.5 BPM/s 的速率平滑，所以两者不会逐帧相等——第 7 轮里 FFT 单路中位 59.5，融合后输出中位 64.3，差异来自另外两路和滤波延迟。

## 一个必须避开的坑

早期版本直接用"1.0–2.5 Hz 带内最强谱峰"当心率参考，得到 76–80 BPM，于是判断板端 60 BPM 偏低 20。

这个结论是错的。呼吸 18.5 次/分时：

- 4 次谐波 = 74 次/分
- 5 次谐波 = 92.5 次/分

1.0–2.5 Hz 正好覆盖 60–150 BPM，呼吸的第 4、5 次谐波就落在里面，而且幅度远大于心搏。所谓"参考值 76–80"其实就是呼吸谐波。

验证时做了两件事来排除：

1. 把呼吸的 1–8 阶谐波拟合并从信号里减掉，残差谱的主峰落到 60–66 BPM，与真值 70 接近
2. 用受试者的手表读数做真值锚定

**结论：先确认呼吸估对了，心率参考才有意义。**

## 各轮结果

| 轮次 | 改动 | 呼吸（板端 / 复算） | 心率（板端 / 复算） | 结论 |
|---|---|---|---|---|
| 3 | 呼吸改 30 s Welch | 10.5 / 10.5 | 62 / 76 | 呼吸对齐，心率参考被谐波污染 |
| 4 | PPI 降权 + 一致性融合 | 11.9 / 15.8 | 60（60 秒后爬到 68.7）/ 80 | 复算参考仍不可信 |
| 6 | 心率窗 30 s + 预热闸门 | 14.4，在 9.4↔19.1 跳变 | 63.2 | 呼吸倍频程误判暴露 |
| 7 | 呼吸频带下边界 0.18 Hz | **18.4 / 18.5** | **64.3 / 64.0** | 两项对齐 |

第 7 轮的有效帧统计：

| 指标 | 中位 | 范围 | 标准差 |
|---|---|---|---|
| 心率 | 64.3 BPM | 54.7–132.7 | 16.2 |
| 呼吸 | 18.4 次/分 | 16.3–18.8 | 0.6 |

心率的标准差被末段 3 帧 132 BPM 的倍频尖峰拉高了；剔除后范围是 54.7–67.6。

## 复现步骤

```bash
cd tools/verify
python replay_board_hr.py --phase phase.csv --snap snap.csv
```

脚本会打印逐秒的板端复现值、真值锚点和偏差。没有原始数据时，脚本只做算法自检，不产生结论。

## 已知未解决项

- **倍频尖峰**：体动时三路可能同时锁到二次谐波，速率平滑器的重锁机制（连续 3 帧一致）会接受它。目前只靠 `motion` 标记提示用户。
- **台阶跳变**：原始位移每分钟仍有数十次 0.8–1.9 mm 的跳变，来源是距离门切换和相位解缠失败，是精度的主要上限。
- **单场景验证**：只验证了 0.6–1.2 米、正面坐姿、单人、静息场景。
